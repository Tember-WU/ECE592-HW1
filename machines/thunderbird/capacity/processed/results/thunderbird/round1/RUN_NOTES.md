# Thunderbird 第一轮：粗扫描

本轮已完成 39 个配置、39,000,000 个计时批次，采集耗时 180.06 秒。工作集为 2 KiB–512 MiB 的 19 个二次幂点，每个大小分别跑随机链和顺序链，另有一个空计时器对照。每个配置独立启动进程，保存 1,000,000 个批次；默认每批 256 次依赖加载。预检短测试不计入本轮。

CPU 32 / NUMA node 0；GCC 11.5.0，原有 -O0 编译选项。ARM 使用 CNTVCT_EL0（25 MHz）；一个计时器刻度为 40 ns，不是核心周期。原始数据和主图单位为 CNTVCT ticks/load，下表仅将其乘以 40 展示为 ns/load。

| 新实测随机链区间 | 中位数（ns/load） | 下一轮用途 |
|---|---|---|
| 64–128 KiB | 1.5625 → 4.6875 | 第一处容量转换候选区间 |
| 1–2 MiB | 6.25 → 38.28125 | 第二处大幅转换候选区间；512 KiB 为 4.6875，1 MiB 已有轻微上升 |
| 32–64 MiB | 40.15625 → 74.84375 | 末级缓存有效转换候选区间 |

4–16 MiB 区域约为 38.44 ns/load；128、256、512 MiB 分别为 87.97、94.69、98.44 ns/load。第二轮的点由这些新实测曲线选择，配置记录了选择理由和全部第一轮证据哈希。区间是加密扫描范围，不是最终容量结论或统计置信区间。

[完整曲线](figures/capacity_s64_b256_huge.png)、[箱线图](figures/boxplots_s64_b256_huge.pdf)、[统计表](summary.csv)、[相邻点比较](transitions.csv)、[验证记录](validation.json)。

全部 39 个映射在测量前后均有完整 2 MiB THP 支撑，并位于 node 0；起止 CPU 均为 32。计时区间内小缺页、大缺页和主动切换均为 0；非主动切换共 2,717 次，单点最多 240 次。每点结束时的频率快照均为 3 GHz，但这不是整个计时区间恒频的证明；保留默认 schedutil governor，时间块中位数和全部尾部样本均已保留。

原始数据解压后共 312,000,000 字节，gzip 后 15,683,378 字节。所有原始数组哈希、样本数、重新计算的统计量、源码/二进制快照，以及原有 386 个 Artemisia 文件的保留状态都已验证。
