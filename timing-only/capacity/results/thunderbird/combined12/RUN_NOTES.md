# Thunderbird 两轮 Cache levels and capacity 实验

已在 **thunderbird.ece.ncsu.edu（AArch64 / ARM Neoverse-N1）** 上按原流程依次完成两轮实验。第一轮 39 个配置，第二轮 57 个配置，共 **96 个配置、96,000,000 个计时批次**，每个配置保存 1,000,000 个原始批次。两轮采集耗时分别为 180.06 秒和 422.04 秒，合计约 10 分 2 秒；不含适配、预检和后处理。

原有 Artemisia 的 x86 内核、配置、原始数据和结果均保留，386 个受保护文件逐一通过 SHA256 校验。修改前的公共脚本、Makefile、README 和 x86 源码另存于 [source_before](../../../data/thunderbird/preflight/source_before/)。ARM 适配和复现环境见 [THUNDERBIRD.md](../../../THUNDERBIRD.md)。

## 实测结论

曲线支持区分三个数据缓存驻留延迟区域，并可观察到更大工作集的高延迟内存区域。**L1D 约 64 KiB，L2 约 1 MiB；末级/系统缓存只报告 32–64 MiB 的有效转换区域，未唯一确定其物理容量。** 层级命名是对依赖加载延迟曲线的解释，不是对硬件规格的读取结果，也不是对指令缓存的测量。

主图和原始数据保留 CNTVCT ticks/load。该机器通用计时器为 25 MHz，一个刻度为 40 ns；下表将每次加载的刻度数乘以 40，展示为 ns/load。它们不是核心周期。

| 区域 | 随机依赖链的实测证据（ns/load） | 解释 |
|---|---|---|
| L1D | 32 KiB 为 1.40625；64 KiB 三次独立运行均为 1.5625；72 KiB 为 3.125；80 KiB 为 4.6875 | 约 64 KiB；64–72 KiB 是采样到的明显转换邻域 |
| L2 | 128–512 KiB 区域为 4.6875；1 MiB 三次独立运行均为 6.25；1.125 MiB 为 14.6875；1.25 MiB 为 21.09375；2 MiB 约 38.28 | 约 1 MiB；1–1.125 MiB 区间出现大幅上升。1 MiB 点已偏离平坦的 L2 延迟，因此这不是严格的“首次上升”界限 |
| 末级/系统缓存 | 4–16 MiB 约 38.44；第二轮 64 B 布局在 32/40/48/56/64 MiB 分别为 39.375/57.344/67.969/72.656/75.0 | 32–64 MiB 存在有效转换，32–40 MiB 已明显离开前一区域；不能将这个区间当作物理容量的上下界 |
| 大工作集 | 第一轮 128/256/512 MiB 分别为 87.969/94.688/98.438 | 更高延迟的内存访问区域；不额外计为缓存层级 |

上述区间是实测采样邻域，不是统计置信区间。64 KiB 和 1 MiB 的重复支持锚点稳定，但紧邻边界的 72 KiB 和 1.125 MiB 加密点各只有一个新种子运行；一百万个连续批次不等于一百万次独立实验。第二轮没有测量 512 KiB–1 MiB 内部的加密点，因此不声称精确定位 L2 最早发生退化的位置。

## 对照与重复

- **长批次：** 64 KiB 的 1024-load 对照为 1.44531 ns/load，对比 256-load 的 1.5625；1 MiB 的两种批长均为 6.25。L1 的少量差异符合固定计时开销和量化影响的可能性；这些对照支持主要延迟区域的存在，不能把所有差异唯一归因于计时开销。
- **空计时器：** 中位数 1 tick（40 ns/interval），P05 为 0，P95 为 1 tick。零刻度来自有限计时分辨率，原样保留；非空计时区间仍严格要求正数。没有扣除空计时器中位数，也没有删除异常值。一个刻度折合 256-load 批次的 0.15625 ns/load、1024-load 批次的 0.0390625 ns/load。
- **布局：** 8 B 布局下，32 MiB 的两次重复均为 38.4375；48 MiB 为 65.78125 / 66.25；64 MiB 两次均为 73.59375 ns/load。它们支持相近的广义末级转换区域。紧凑布局增加空间复用机会，其曲线与 64 B 布局分开分析。
- **页大小：** 64 B 随机链在 32/48/64 MiB 的基础页结果为 55.0/76.40625/84.53125，完整 THP 结果为 39.375/67.96875/75.0 ns/load。基础页引入了明显的额外影响；地址转换是可能因素，实验没有将其与其他因素完全分离，因此不能把每处上升都解释成新的缓存层级。
- **时间稳定性：** 8 B 布局 32/48/64 MiB 的重复，其十个时间块中位数范围分别为 38.281–38.750、65.625–68.125、73.438–73.906 ns/load。64 B 布局 64 MiB 在第一轮和第二轮的中位数为 74.84375 / 75.0。完整的逐点、逐块数据均已保留。

## 完整性与运行条件

两轮使用相同 ARM 源码和二进制、GCC 11.5.0 与原有 `-O0` 编译选项、CPU 32 / NUMA node 0、25 MHz 计时器。ARM 汇编的计时区间内每组为 16 个相互依赖的加载，没有栈访问或函数调用。第一轮保持原有 2 KiB–512 MiB 粗扫描，第二轮由新曲线选择 64–128 KiB、1–2 MiB、32–64 MiB 的加密范围，参数文件保存了选择理由和第一轮证据哈希。

93 个配置使用完整 2 MiB THP，3 个配置显式使用基础页；所有映射在计时前后均符合页策略并位于 node 0，起止 CPU 均为 32。计时区间的小缺页、大缺页和主动切换均为 0。非主动切换第一轮 2,717 次、第二轮 4,897 次，总计 **7,614 次**，单点最多 256 次。数据完整性校验通过不等于没有调度干扰，尤其尾部值仍可能受影响。

保留机器原有 `schedutil` governor，没有修改内核设置。每点结束时频率快照均为 3 GHz，开始前快照为 1–3 GHz；这些快照不能证明整个计时区间恒频。计时器刻度本身与核心周期分开记录，频率校准与 CLOCK_MONOTONIC_RAW 的差异小于 1%。初始兼容性检查的 `lscpu` 输出包含内核报告的缓存总量；本次加密点选择和上述结论依据新测量曲线，没有将这些总量或 Artemisia 的容量答案作为结果。

所有 96 份原始数组的哈希、样本数及重算统计量已验证，采集清单全部完成，源码/二进制快照通过校验，两轮环境可以合并。原始数组解压后共 768,000,000 字节，gzip 后 **52,876,192 字节**（约 50.43 MiB）。13 项自动检查和 6 个原生短预检均通过；短预检不计入正式两轮的配置或批次数。
