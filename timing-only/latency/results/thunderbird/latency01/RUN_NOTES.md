# Thunderbird：七组 Hit / Miss-next-level latency 实验

`latency01` 已完成全部七组、30 个配置，采集耗时 **223.41 秒（约 3 分 43 秒）**。每点预热后保存 1,000,000 个批次；21 个单列配置和 9 个双列配对配置，共保存 **30,000,000 个批次、39,000,000 个计时区间**。执行时间为 2026-09-10 21:06:42–21:10:25 UTC。保持原配置的 `order_seed=59280`，30 个配置按固定随机顺序逐点串行执行，每点使用独立进程和新分配的指针环。

原有 AArch64 内核已经可以使用，正式内核、配置、采集器和分析器均未修改。唯一的原文件改动是 ARM 功能测试的短批次适配，原测试已留档；其余 150 个原文件（包括 Artemisia 代码、配置、数据和结果）哈希均未变。见 [本机运行说明](../../../THUNDERBIRD.md) 和 [最终审计](run_audit.json)。

## 单位与七组完成情况

原始数组、CSV 和原流程图表使用 **CNTVCT ticks/load**，不是核心周期。本机计时器频率为 25 MHz，**1 tick = 40 ns**，以下表格将 ticks/load 乘以 40，给出 ns/load。计时器校准相对 CLOCK_MONOTONIC_RAW 的偏差小于 1%。所有延迟仍包含循环与计时边界开销，没有从原始样本扣除固定计时器开销。

| 组 | 配置数 | 内容 |
|---|---:|---|
| calibration | 12 | 空计时器；三级候选的长批次、顺序链、四独立流对照；大工作集顺序/四流对照 |
| l1_hit | 3 | 16/32 KiB，含 16 KiB 新种子重复 |
| l2_hit | 3 | 256/512 KiB，含 256 KiB 新种子重复 |
| llc_hit | 3 | 4/8 MiB，含 4 MiB 新种子重复 |
| l1_miss | 3 | 256/512 KiB 的 FIRST/REREAD 配对访问，含新种子重复 |
| l2_miss | 3 | 4/8 MiB 的 FIRST/REREAD 配对访问，含新种子重复 |
| llc_miss | 3 | 256/512 MiB 的 FIRST/REREAD 配对访问，含新种子重复 |

工作集依据本机此前的容量实验选择；配置中的 capacity inference SHA256 与实际文件完全匹配。层级和命中/未命中名称是由计时证据支持的候选分类，没有使用 PMU 验证每一次访问究竟由哪一级提供数据。

## 驻留候选延迟

| 组 | 各进程中位数范围（ns/load） | Primary 的 P05–P95（ns/load） |
|---|---:|---:|
| L1 resident | **1.40625** | 1.40625–1.71875 |
| L2 resident | **4.68750** | 4.53125–4.68750 |
| LLC resident | **38.43750** | 37.96875–39.06250 |

三个层级各自的 alternate footprint 和新种子 repeat 均给出相同的整体中位数，支持三种可区分的驻留延迟区域。中位数相同不代表分布完全相同；有限计时分辨率也会使不同运行落在同一个刻度上。L1 的两个点还有首个时间块偏高的情况，见下文。

## FIRST、立即重读与 next-level 对比

每个样本先沿大指针环访问下一批 N 个目标，再复位游标，立即重读完全相同的一批地址。下一样本从 FIRST 结束位置继续。工作集和完整环的复用距离提供缓存压力；没有在每个样本前执行 flush 或构造特定 cache set 的逐出集合。

| 压力组 | FIRST 中位数范围 | REREAD 中位数范围 | 配对 FIRST−REREAD 的中位数范围 | FIRST 中位数−前一级驻留 Primary 中位数 |
|---|---:|---:|---:|---:|
| L1 miss / L2 candidate | 4.68750 | 1.56250 | 3.12500 | **3.28125** |
| L2 miss / LLC candidate | 38.43750 | 1.56250 | 36.87500 | **33.75000** |
| LLC miss / memory candidate | 94.21875–97.50000 | 2.50000–2.81250 | 91.71875–94.68750 | **55.78125–59.06250** |

本表所有数值单位均为 ns/load。倒数第二列是同一样本内的有符号配对差值分布；最后一列是减去另一个进程测得的前一级驻留中位数。这两种量不同。最后一列可作为 **next-level 额外访问成本的经验对比**，只有在预期驻留类别成立的范围内，才适合解释成对应层级的 miss penalty；它不是实际流水线停顿周期，也不是配对差值的置信区间。

L1/L2 压力组的 FIRST 与相应下一层驻留参考一致，立即重读则接近 L1 参考。REREAD 的 1.5625 比独立 L1 驻留的 1.40625 高 0.15625 ns/load，恰好对应 256-load 批次的一个计时器刻度；不能据此把全部 REREAD 确认为纯 L1 命中。

大工作集的 FIRST：256 MiB primary 为 94.6875，repeat 为 94.21875，512 MiB alternate 为 97.5 ns/load。它们是内存占主导的候选，不能据此声称唯一、纯粹的 DRAM 延迟。其立即重读仍为 2.5–2.8125，高于小工作集的 L1 参考，地址转换、冲突或周边工作负载等影响尚未分离。

L1 压力组的 FIRST 慢于 REREAD 的样本比例为 0.999907–0.999967；L2 和 LLC 压力组均为 1.0。全部负配对差值、尾部样本和异常值均保留。

## 方法对照与计时开销

| 候选区域 | 256-load 随机依赖访问 | 1024-load 随机依赖访问 | 顺序链 | 四独立流 |
|---|---:|---:|---:|---:|
| L1 | 1.40625 | 1.36719 | 1.40625 | 0.46875 |
| L2 | 4.68750 | 4.53125 | 1.56250 | 1.40625 |
| LLC | 38.43750 | 38.32031 | 2.03125 | 9.53125 |
| 256 MiB | 94.68750（paired FIRST） | 未配置 | 4.37500 | 24.53125 |

单位为 ns/load。四独立流数值是吞吐诊断，不是单条依赖链的 hit latency；大工作集参考使用原流程中的 paired FIRST。长批次结果略低但保持相同的驻留区域次序。顺序链在大工作集明显快于随机链，说明访问模式对结果有很大影响；空间局部性和预取可能参与其中，不能把顺序控制的吞吐直接替代随机依赖访问延迟。

空计时器中位数为 1 tick/interval（40 ns），P05–P95 为 0–1 tick。零刻度区间合法并保留。非空正式测量均为正刻度。计时器一个刻度折合 256-load 批次的 0.15625 ns/load，或 1024-load 批次的 0.0390625 ns/load；报告的小数位不代表相同精度的独立单次加载计时。

## 页分配、调度与时间稳定性

所有点使用 CPU 32 / NUMA node 0，完整 2 MiB THP 支撑在测量前后均已验证；NUMA 页数也与整个映射大小相符。全部点通过了指针游标最终位置检查，配对模式的 FIRST/REREAD 终点一致。保留原 `schedutil` governor，未修改系统设置；短预检 CPU 32 busy 为 0%。每点结束频率快照均为 3 GHz，开始前快照为 1 或 3 GHz；快照不能证明整个测量过程恒频或独占 CPU。

计时区间的小缺页、大缺页和主动切换均为 0。非主动切换总计 **2,506 次**，单点最多 250 次。数据完整性通过不等于没有调度或共享资源干扰。

以下三个点触发原分析器的“十个时间块中位数比值 >1.2”描述性标记：

- `l1_hit__primary`、`l1_hit__repeat`：首个时间块为 1.71875 ns/load，之后九块均为 1.40625，最大/最小比为 1.2222。
- `calibration__l1_independent`：首块为 0.625 ns/load，之后九块均为 0.46875，比值为 1.3333。

这些首块偏高可能涉及调频或短期干扰，现有记录不能唯一归因。小延迟下，一个计时器刻度也会造成较大的相对变化。上述标记不是显著性检验，没有据此剔除首块或重跑取较好结果。其余 FIRST 点未触发该标记，完整时序数据保存在 `temporal_medians.csv`。

## 原生检查、保留与输出

六项功能检查及八个原生短预检通过，包含所有模式、1024-load 批次、512 MiB 大页配对测试及基础页配对测试。原生反汇编确认依赖链与四流计时区间各有 16 次加载，分别使用 1/4 条依赖流，无计时区间内栈访问或调用。

最初的功能测试在 ARM 上因 16-load 四流批次过短出现零刻度而失败；仅 ARM 测试夹具改为正式批长 256，x86 测试仍为 16，原测试与失败日志均留档。正式内核、30 点配置及每点 1,000,000 批次没有改变。预检样本不计入正式计数。

分析器已重开全部 30 个压缩数组，核对哈希、行列维度、采样数和统计量（包括有符号配对差值），检查源码/二进制快照及 CPU/NUMA/页证据；附加审计确认计划点及执行顺序完全一致，原有文件保留检查通过。原始数据共 **312,000,000 字节**，gzip 后 **15,432,149 字节**。`summary.csv` 的 48 行包含 9 行计算得到的配对差值，它们不是额外采集的区间。
