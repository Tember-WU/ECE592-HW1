# Unexecuted Hazel validation procedure

**Final project status:** We did not complete the Hazel experiments because we ran out of time. This procedure is retained for documentation only; it is not planned remaining work or evidence of completed experiments. The laws are named Patel–Wu.

No GitHub freeze or Hazel measurement is claimed by this package. The older local checksum snapshot is not proof of a GitHub pre-experiment freeze. A later commit cannot retroactively repair a prediction made after seeing results.

1. Use the Patel–Wu law names in REPORT.md and OUR_LAWS_SLIDE.md. Review the two equations, target-year convention and full numerical prediction table before any Hazel reveal.
2. Commit the law text, `laws.json`, `tables/hazel_predictions.csv`, `tables/lab_evidence.csv`, `provenance.json`, this protocol, figures and build/validation scripts to the team GitHub repository, together with the existing Section 9 prediction package. Record the full commit SHA, GitHub commit URL and timestamp in a separate validation record. Confirm the commit is visible remotely before running experiments. No such commit or push was performed during preparation of this folder.
3. Check actual Hazel availability. At minimum measure both metrics for one held-out target; Turin is the only listed target beyond the latest lab year. If unavailable, record that fact and use another accessible held-out generation. Multiple targets provide a stronger test. Keep the established generation-year convention, including Ice Lake’s 2020 family coordinate versus 2021 implementation launch.
4. Run the existing timing-only capacity and resident-latency methodology on an allocated Hazel compute node with the same workload controls. Preserve benchmark source revision, command, scheduler job, CPU identity, affinity, working-set sweeps, sample counts, raw timings, resident-regime evidence, and timestamps. Use matching L1- and L2-resident latency measurements to compute the ratio. Record timer units/frequency information. Do not replace an uncertain timing inference with a published cache value; later PMU/system checks belong in separate verification fields.
5. Copy `hazel_results_template.csv` to a results file and fill observed value, bounds, raw source, measurement UTC and pre-experiment freeze SHA. Every observation must be traceable to a real run after the remote freeze. Missing values remain blank. Capacity units are KiB/core; latency ratios are dimensionless.
6. Evaluate without refitting the original laws. Report signed percent error `100*(observed/predicted-1)` for both metrics and `log2(observed/predicted)` for capacity. Compare measured brackets with the frozen envelope, while acknowledging that the envelope is not probabilistically calibrated. Use this preregistered descriptive rubric: **supports** when the central observation is inside the prediction envelope with reliable, comparable inference; **weakens** when the central observation is outside but uncertainty brackets overlap, or comparability is questionable; **falsifies the stated predictive range for that target** when reliable observed and predicted ranges are disjoint. A single result cannot establish universality. Do not redefine thresholds after seeing the reveal, and distinguish failure of a range from failure of every possible model of the trend.
7. Overlay actual Hazel observations on the same two law figures as filled stars (Intel) or diamonds (AMD), with labels and measurement error bars. Keep lab markers and the original frozen model. Use solid curves within the lab years and dashed lines only beyond 2023. In-range held-out predictions can be shown with open markers; do not draw a dashed overlay through measured years. Explain each verdict, likely class/topology/pipeline effects, and uncertainty.
8. Only after the held-out evaluation, issue a separately labeled further forecast for about five years after the newest measured generation. Preserve frozen predictions unchanged, state whether you retain or revise the model, and show at least three observations plus a dashed future continuation. Finalize the Our Laws slide with actual verdicts and freeze → prediction → reveal evidence.

The preparation script deliberately does not ingest a results file or fabricate reveal markers. The final overlay must use the verified observations and their actual generation years once available.
